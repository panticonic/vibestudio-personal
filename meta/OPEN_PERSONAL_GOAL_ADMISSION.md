# Personal artifact and automation admission

The shared mechanism is native application proof plus independently bound goal-meaning review, not a prescribed report label or an operation transcript. Both open runtime producers now use Base's `bindObservedContentReview`; their public typed reports remain available without making unrequested reports obligatory.

Inventory before edits: the Personal `open-personal-automation-runtime/managed.ts` and `open-personal-artifacts-runtime/managed.ts` producers are called by System-testing's `workers/system-test-runner/index.ts` personal fixtures and registered by `skills/system-testing/tests/web-brief-managed.ts`. Literal obligations live in the two `open-goal-personal-*-worlds.ts` factories. Host's exporter registers world kinds `personal-automation` and `personal-artifacts`; its observed-content binder must independently bind the selected native evidence. Base `observed-content-review.ts` performs assessment; no serving engine or model scoring implementation consumes these application fixtures.

Automation: retain current owned definitions, permitted scheduling actions, dependency/readback/recovery guards, protected default monitor and no-dispatch proof. Supplied findings must reference an issued queue and exact native current monitor identity/revision/state, including genuinely absent names. The semantic interpretation of statuses, disposition and completeness is reviewed against the goal; no golden count or label is required. The native transition-once and recovery protocol is unchanged and still requires separate audit against each literal goal.

Artifacts: retain actual native browser-library and collection snapshots, grants, CAS, protected competing changes, bookmark identity/URL, final requested titles, notes and sibling placement. Remove exact mutation-transcript and refresh-count requirements. Every supplied link remains bound to its actual bookmark and stored note. Accurate native holds no longer require identical titles or a keyword repeated from the goal. No new operation is granted. Supplied facts remain checked even when the application return is optional.

Obligations are explicit in all 26 automation worlds and all 9 artifact worlds, rather than inferred from whether writes happened or a reference was held. The unchanged literal user goal decides whether a public finding is requested. Requested native notes remain effects, not a mandatory generic result object. Goal meanings are always reviewed, including effects-only cases. IDs, goal texts and splits are unchanged.

Validation: 24 actual component tests passed through a Host-owned projection, including all nine artifact native fixture qualifications, an additional authorized idempotent link, real CAS and protected competing update, forged references, current-revision checks, optional incorrect returns and required-return absence. The tests inject native port storage, not the assessment logic. This is not a full native integration or a claim that the remaining Personal admission families are closed.

## Immutable history findings

All 24 Personal-history worlds request an answer, so their return remains required. `matchHistoryFindings` and `joinHistoryEvidence` have only the open history runtime and their component tests as consumers (source search before edits). The System-testing worker prepares this runtime at its `personalHistory` branch; its ordinary open-goal registration is `personal-history`. The returned milestone labels must identify assigned native milestones and every citation must match an actual inspected source's event, path, digest, line and bytes. Protected main/working history remains exact.

Private expected statuses, relation/action labels, finding cardinalities, preferred quotations and file-read routes are no longer semantic acceptance oracles. They remain reference-fixture data for model-free qualification. The mandatory review receives actual catalog identity, repository, milestones, discovery, operations and inspected source bytes, plus the actual requested return. Native discovery integrity is checked when performed; legitimately known owned milestone/path reads remain permitted.

Validation: all 24 actual history fixture qualifications plus alternative source-line/read-path, forged digest, protected-head and helper controls passed (28 component tests, 1.84s/154.6MiB). An initial run exposed a stale qualifier negative that changed a semantic status instead of corrupting evidence; it now always fabricates a citation, and the complete rerun passed. No historical packet was rewritten or reassessed.
