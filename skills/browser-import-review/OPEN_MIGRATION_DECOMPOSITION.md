# Open browser migration and handoff

| Part | Implementation |
| --- | --- |
| Discover the owned profiles and choose the work | Typed Natlang chooses source, operation and public categories from the user's request and actual profile, approval and retention facts. The binding ties the observed profile revision to the authorized operation and exact category set. |
| Inspect, execute, or recover | The installed browser import skill interprets source availability, exact approved preview counts and native retained progress. The installed coordinator owns operation identity and stores actual bookmark batches in the owned BrowserDataDO. A cancelled receipt and its stored batches are inspected without dispatching again. |
| Report the source outcome | Carry the actual preview, exact approval, receipt ID, phase and interpreted counts through a typed Natlang result. |
| Decide what to hand off | A typed Natlang child selects a bookmark and a collection panel from independent retained bookmark and live collection observations. Separate same-title collection children are distinguished by parent. |
| Bind the effect and verify it | The service checks the same persisted import receipt and exact bookmark URL before applying a revision-bound note through the installed collection binder. The independent oracle rereads the native import receipt, stored bookmarks, collection delivery, and protected state. |

The pinned sources are `personal-live-browser-import-review` for source and approval checks, and `personal-live-browser-handoff` for the durable bookmark-to-panel dependency. The owned transport uses disposable browser import entities and local collection panels. Preview authority covers category counts and warnings observed by the existing provider. Collection notes use the exact URL recorded in the browser store.
