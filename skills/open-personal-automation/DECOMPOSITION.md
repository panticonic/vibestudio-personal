# Coordinate an authorized Personal automation handoff

| Responsibility | Implementation |
| --- | --- |
| Interpret the requested scheduling outcome and resolve the exact monitors | A natural-language planner works from the controller's live owned inventory, teams, dependency metadata, and review receipts. |
| Decide which changes can proceed and in what order | A typed decision reads the goal, latest scheduling state, and prior work. Dependencies must be active before resuming their consumers. |
| Control one definition and recover from a lost response | A nested Natlang callable dispatches at the reviewed revision and performs a fresh read even if the response is interrupted. A second reasoning stage distinguishes a verified effect from changed or inconclusive state. |
| Bind live receipts and effect boundaries | TypeScript calls the installed Missions controller. It validates the observed basis, exact revision, dependency state and assigned permissions. The service accepts only pause and resume on owned manual definitions. |
| Verify independently | The fixture checks persisted definition, scheduling and absence of run dispatch, controller attempts, protected default, exact observation coordinates and the full goal report. |

The installed system-test worker provisions the owned manual definitions
and pauses them before the disposable workspace is destroyed. The durable caller compiles their
authority plans. The eval session checks the seeded records against the live
controller before exposing the queue. Review and
discovery expose names, team, dependencies, current definition digest and
reviewed digest. Desired outcomes and scoring rules stay outside model context.
