# Browser migration evidence and handoff scope

The migration catalog, retained import receipt and collection snapshot establish application facts. A separate discovery call count is not authority. Binding the same sealed source/operation/categories again must replay its request rather than fail; changing the binding remains rejected.

Each handoff inspection issues a revision tied to its actual retained import receipt and native collection snapshot. Further inspections do not revoke earlier issued evidence. Staging accepts any issued revision only when the import evidence still matches, the target/bookmark belongs to that view, and the collection's native compare-and-set accepts the original unchanged snapshot. A completed delivery can be read again only while its actual target note and all neighbors still match the delivered result.

Outcome verification retains actual native import verification, original source/category identity, protected other profiles, current collection state, exact requested bookmark/target/note and native delivery receipt. It does not require a particular number of discovery, binding, outcome or handoff-inspection calls. These changes do not authorize additional import operations or targets.
