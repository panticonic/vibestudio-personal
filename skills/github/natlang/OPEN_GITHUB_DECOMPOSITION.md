# Open GitHub and local Git goals

The pinned `personal-live-github-diagnosis` binds the installed local URL normalizer and GitHub credential preflight. The pinned `personal-live-github-setup` calls the installed status and setup router using an exact operation receipt. The installed terminal workflow already authorizes one bounded native check by its sealed receipt. The new goals combine these paths with real local Git refs and a private owner handoff.

| Part | Implementation |
| --- | --- |
| Discover | A scoped service exposes disposable local repository and account aliases. Natlang matches the actual repository, intended owner and requested GitHub work. |
| Inspect and protect local work | The existing native terminal binder runs fixed Git commands in a disposable directory. A typed Natlang child interprets working and staged changes, detached or divergent refs, and current remote ownership. |
| Review account setup and permissions | The native GitHub URL normalizer, publish preflight and setup router operate on inert owned account summaries. Natlang reads the status and uses the existing access chooser, troubleshooting and setup flow to decide the smallest viable handoff. |
| Handle retained approvals | A typed Natlang child compares approval history with latest owner evidence and chooses whether to hold or offer the exact next step. Current ownership, approval and capability must agree for readiness. |
| Persist and verify | Only a requested handoff can write a revision-bound local receipt. A fresh Git snapshot, owned account-history readback and exact handoff bytes verify that all protected state stayed intact. Negative reference runs reject foreign basis, forged account and incorrect decision. |

The Git fixture creates real local commits and tracking refs directly. It never fetches or sends anything. GitHub account data is synthetic, contains no passwords or tokens, and does not enter the central credential store.
